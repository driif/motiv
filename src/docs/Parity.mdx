# Parity

Every style is meant to cover the same set of component categories. An app should find a button, a
card or a slider whichever entry it imports: `@driif/motiv` (kinetic), `@driif/motiv/drawn` or
`@driif/motiv/matrix`. New parity components use the generic category name in every entry
(`Slider` from all three, same props). Signature-effect components such as `InkSplatterButton`,
`GlitchThemeToggle` or `MagneticButton` stay style-specific.

All three styles already share the component tokens (see Docs/Theming), so an override like
`--motiv-button-border-color` reaches every button.

## Matrix

Every cell leads with the generic name; a flavored name in parentheses is the same component
under its own name, and ² marks a style's extra component in that category. Drawn `NavItem` is a single nav link or button; drawn
`Nav` is the list built from it. Kinetic `Switch`, `Slider`, `Nav` and `Checkbox` are the same components as
`LiquidSwitch`, `MomentumSlider`, `GlideNav` and `SpringCheckbox`, and matrix `ThemeToggle` and
`MenuButton` are `GlitchThemeToggle` and `SignalBurger`, under the generic name. Kinetic
`TextField` has the `FloatingField` look without its validity check, and kinetic `TextField` and
`Progress` take the drawn props. Kinetic and matrix `Tabs`
wrap `ElasticTabs` and `HudTabs` with the drawn `Tabs` props; matrix `Nav` wraps `ChevronNav` with
the `GlideNav` props. Kinetic and matrix `Select` and `Tooltip` take the drawn props; matrix `Select`
wraps `TerminalSelect`, whose field shows an option's `code`, falling back to its `label`, as its own
look. Drawn and matrix `Accordion`, `Stepper` and `Carousel` take the kinetic props. Kinetic `Chips`
is `FilterChips` under the generic name; drawn and matrix `Chips`, `OtpInput` and `CommandMenu` and
matrix `SegmentedControl` take the kinetic props, and kinetic `Link` takes the drawn props.
