# Theming

All motiv CSS lives in `@layer motiv.tokens`, `motiv.base` and `motiv.components`. Any rule an app
writes outside a layer wins over them, without `!important`.

Theming works on three levels: base tokens, derived tokens and component tokens.

## 1. Base tokens

Base tokens are the only inputs. Override them on `:root` to rebrand every component:

```css
:root {
  --motiv-color-primary: #2563eb;
  --motiv-color-on-primary: #ffffff;
  --motiv-radius: 0.5rem;
  --motiv-font-body: 'Inter', sans-serif;
}
```

## 2. Derived tokens

`--motiv-color-primary-subtle`, `--motiv-color-text-muted`, `--motiv-color-surface-hover`,
`--motiv-radius-{sm,md,lg,full}`, `--motiv-shadow-{sm,md,lg}` and `--motiv-focus-ring` are computed
from the base tokens with `color-mix()` and `calc()`. Override a base token and they follow.

They are computed on `:root` and on every element with a `data-theme` attribute. Overriding a base
token on any other element does **not** re-derive them there: a `--motiv-color-primary` set on a
plain `<div>` changes button colors and hover shades inside it (those are derived on the button
itself), but `--motiv-color-primary-subtle` and `--motiv-focus-ring` keep the root's primary.
Add `data-theme` to the wrapper, or set the derived tokens too.

## Dark mode

Set `data-theme` on `<html>`:

```html
<html data-theme="dark">
```

Without a `data-theme` attribute, motiv follows `prefers-color-scheme`. `data-theme="light"`
forces light.

A subtree can use its own theme:

```html
<section data-theme="dark">…</section>
```

## 3. Component tokens

Component tokens restyle one kind of component without touching the rest. They have the same names
in all three styles, so an override works whichever stylesheet the app imports. Each falls back to
the base or derived token the component uses today, so nothing changes until you set one. Set them
on `:root` for every instance or on any ancestor for one subtree:

```css
:root {
  --motiv-button-border-color: green;
  --motiv-text-field-accent: green;
}

.settings-page {
  --motiv-button-radius: var(--motiv-radius-sm);
  --motiv-card-padding: 2rem;
}
```

Every category uses the same suffixes, and only where a component paints that property:

| Suffix | Paints |
|---|---|
| `-bg`, `-bg-hover` | the fill, at rest and on hover |
| `-color` | the label or text |
| `-border-color`, `-border-color-hover`, `-border-width` | the outline, the frame or (matrix) the HUD corners |
| `-radius` | the corner radius |
| `-accent` | the checked, selected, active, focused or filled state |

A component token overrides every variant at once: `--motiv-button-bg` fills primary, secondary,
danger, outline and ghost buttons alike. Hover fills and borders derive from the overridden `-bg`
and `-border-color` unless `-bg-hover` or `-border-color-hover` is set. Drawn's sketched corners and matrix's square ones are only
the `-radius` fallbacks, so setting a radius replaces them.

Unless stated otherwise, kinetic components are named first, then drawn (`@driif/motiv/drawn`), then
matrix (`@driif/motiv/matrix`). ✓ means the style reads the token, — means its components have no
such property.

## Drawn style

`@driif/motiv/drawn.css` is the whole stylesheet for apps using `@driif/motiv/drawn`: the tokens
above, `base.css`, the drawn components and the Caveat font. Import it instead of `styles.css`,
never alongside it — both style the same `motiv-*` class names.

| `--motiv-color-secondary` | `#b83c0c` | `#f6bf8e` |
| `--motiv-color-on-secondary` | `#ffffff` | `#3a1a05` |
| `--motiv-color-danger` | `#c11f1f` | `#ff8f85` |
| `--motiv-color-on-danger` | `#ffffff` | `#3b0906` |
| `--motiv-color-bg` | `#fbfaf6` | `#16181d` |
| `--motiv-color-surface` | `#f3f1ea` | `#1f2228` |

## Plain CSS overrides

Because motiv's rules are layered, a normal app rule wins:

```css
.motiv-btn {
  text-transform: uppercase;
}
```

## Interactive cards

`<Card interactive>` only adds hover and focus styles. A card rendered as `div`, `section`,
`article` or `li` is not focusable or clickable on its own: give it `tabIndex={0}` plus a role and
keyboard handling, or put a real link or button inside it.
